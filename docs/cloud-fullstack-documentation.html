2 · Architecture

Two-backend design

The Spring Boot backend is a new self-contained Maven module inside the existing repository. Both backends run simultaneously without conflict:

BackendPortPurpose
Next.js (Front-End Capstone)3000React frontend + Node.js Route Handlers (unchanged)
Spring Boot (Cloud FullStack Capstone)8080Java REST API, independently testable
Both connect to the same PostgreSQL database: chapter_and_co

Data flow

Browser → Next.js (port 3000) → Prisma → PostgreSQL chapter_and_co
        → Spring Boot (port 8080) → Spring Data JPA → PostgreSQL chapter_and_co
        → (same tables, ddl-auto=validate, no schema changes)

3 · JPA Entities → PostgreSQL Tables

All JPA entities are mapped to the existing tables created by Prisma migrations. ddl-auto=validate ensures Hibernate validates the schema but never modifies it.

BookbooksManyToMany categories, ManyToOne author, price Decimal(10,2)
AuthorauthorsOneToMany books

AddressaddressesManyToOne user, fullName, line1, city, postalCode, country
Orderordersstatus enum, subtotal, shippingCost, giftPointsUsed, total
OrderItemorder_itemsunitPrice captured at time of order

5 · Security

ConcernImplementation
AuthenticationStateless JWT via JwtTokenProvider (jjwt 0.12.6, HS256)
Password hashingBCrypt, cost factor 12
AuthorizationJwtAuthenticationFilter sets SecurityContext per request
Server-side pricingOrderService.placeOrder() fetches prices from DB — client values ignored
IDOR preventionAll user-scoped queries filter by userId from JWT
Cancellation abuse48-hour window enforced in OrderService.cancelOrder() — 400 Bad Request if expired
Input validationJakarta Bean Validation on all DTOs (@NotBlank, @Email, @Size, @Min/@Max)
Payment dataNo real card data — demo flow only, demoCardLast4 field clearly labelled
CORSConfigured for http://localhost:3000 (Next.js frontend)
SecretsAll via application.properties / environment variables
