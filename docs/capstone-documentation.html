3 · Architecture

Data flow

Browser → Server Component → Prisma → PostgreSQL
       → Client Component → /api/ Route Handler → Prisma → PostgreSQL
       → Zustand (cart, localStorage)

Key architectural decisions

DecisionRationale
Server Components for pagesDirect Prisma access — eliminates API waterfall, improves page load
Client Components only where neededCart, filters, and forms need interactivity; everything else is static server rendering
Server-side pricing in /api/checkoutClient prices ignored; all totals recalculated from DB to prevent manipulation
JWT sessionsStateless, scales horizontally, no session table overhead
Zustand + localStorage for cartCart persists across page refreshes and before login
Zod schemas shared FE + BESingle source of truth; same schema validates form and API route

5 · API Endpoints

MethodPathAuthDescription
GET/api/books—List books — supports search, category, author, sort, page
GET/api/recommendationsOptionalPersonalized recommendations; falls back to featured books
GET/api/addresses✓List authenticated user's addresses
POST/api/addresses✓Create a new delivery address
GET/api/gift-points✓Current gift point balance + transaction history
POST/api/checkout✓Place order: server-side pricing, stock check, Prisma transaction
GET/api/orders✓Full order history for authenticated user
GET/api/orders/[id]✓Order detail with items, payment, address
PATCH/api/orders/[id]✓Cancel order — 48-hr window enforced, stock + points restored
POST/api/auth/register—Register new user with Zod validation + bcrypt
*/api/auth/[...nextauth]—Auth.js Credentials handler (login, session, logout)

All inputs validated with Zod. All protected endpoints return 401 if unauthenticated. All user-scoped queries filter by userId to prevent IDOR. Full spec in docs/openapi.yaml.

6 · Security Notes

ConcernMitigation
Password storagebcrypt, cost factor 12
Payment dataNo real card data collected or stored — demo flow clearly labelled
Server-side pricingAll prices recalculated from DB on checkout; client prices ignored
IDOR preventionAll user-scoped queries filter by userId
Input validationZod on all API route handler inputs, server-side
Protected routesmiddleware.ts + auth() in route handlers
SecretsNo hardcoded secrets — all via environment variables
Cancellation abuse48-hour window enforced server-side in PATCH handler
